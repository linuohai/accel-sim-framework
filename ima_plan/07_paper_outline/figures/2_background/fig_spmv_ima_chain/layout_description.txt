### 2. Spacing Recommendations
- **Vertical Padding:** Maintain exactly 32 grid units (Y: 45 to 77) between the bottom of A_col[] and the top of x[]. This massive vertical whitespace is strictly reserved for the red indirection arrows to prevent visual clutter.
- **Cell Padding:** Text inside array cells must have 10% padding from the cell borders to ensure the 9pt bold monospace text does not touch the 1.0pt black borders.

### 3. Grouping Strategy
- **Group 1 (Logical Control):** The code box at the top.
- **Group 2 (Memory Access 1):** A_col[] array, its labels, the green "j" arrow, and the "① index load" annotation.
- **Group 3 (Memory Access 2):** x[] array, its labels, and the "② data load" annotation.
- **Group 4 (Dependency):** The red arrows and the right-side curly bracket.

### 4. Arrow Routing (The Critical Visual)
To make the scattered nature obvious without crossing lines becoming an unreadable mess, route the 5 red arrows (#C0392B, 1.5pt) with specific Bezier curves:
1. **A_col[0]=1 → x[1]:** Start (25, 40), End (31, 77). Slight S-curve.
2. **A_col[1]=4 → x[4]:** Start (31, 40), End (49, 77). Arch downward, apex at Y=55.
3. **A_col[2]=7 → x[7]:** Start (37, 40), End (67, 77). Wide arch downward, apex at Y=60.
4. **A_col[3]=2 → x[2]:** Start (43, 40), End (37, 77). Arch *leftward*, apex at Y=50 (crosses under arrow 1 and 2).
5. **A_col[4]=5 → x[5]:** Start (49, 40), End (55, 77). Direct S-curve.

*Rule:* Arrowheads must strictly terminate at the top border of the x[] cells. Do not let arrows overlap the text inside the cells.

### 5. Visual Hierarchy
1. **Primary (Highest Contrast):** The red curved arrows and the dark purple (#A569BD) "accessed" cells in x[]. This immediately draws the reviewer's eye to the "scattered" access pattern.
2. **Secondary:** The arrays themselves (light blue and light purple blocks) and the C code snippet.
3. **Tertiary:** The structural labels, annotations, and legend.

### 6. Aspect Ratio
- **3:4 (Width:Height).** The vertical layout (Code -> A_col -> Arrows -> x -> Legend) naturally fills a taller-than-wide bounding box, perfectly suited for a single column in a two-column IEEE/ACM paper format (approx 3.5 inches wide by 4.6 inches tall).

### 7. Critical Visual Design Decisions
- **Highlighting the Scatter Pattern:** By coloring the unaccessed x[] cells light purple (#D7BDE2) and the accessed ones dark purple (#A569BD), the non-linear, scattered footprint on the dense vector becomes instantly recognizable even before reading the text.
- **Arrow Clarity:** Limiting the red arrows to the first 5 iterations prevents a "spaghetti" effect while still proving the accesses are non-sequential.
- **Print Readability:** Using 9pt bold text for all array values and 1.0pt thick borders ensures that when the figure is scaled down to 3.5 inches wide, the numbers (1, 4, 7, etc.) remain perfectly legible.
